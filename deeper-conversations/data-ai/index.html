Your data & AI

A plain-English guide · Last updated: 7 September 2026

This page explains what enters Deeper Conversations, where it goes, what AI sees and what the product deliberately does not do.

The principle: collect less, use it for a clear reason, keep the user in control, and never confuse an AI draft with a finished human contribution.

2. Optional LinkedIn archive import

You do not need to upload a LinkedIn archive. If you choose to, the current importer recognises selected CSV exports such as Connections, Comments, Reactions, Shares, Posts and Articles.

Depending on the files you select, this can create:

  • People records: name, organisation, position, profile URL and connection date;
  • History records: your comment/post/repost text, reaction type, date and relevant URL;
  • Voice samples: selected text from your own comments and posts, used to improve Voice DNA.

Private message export files are deliberately ignored. If a selected filename indicates messages, the importer skips it rather than bringing that material into the workspace.

3. Optional LinkedIn notification signals

A user can optionally configure a user-controlled notification workflow. It converts selected LinkedIn notification emails into a small set of structured signals such as:

  • actor or author name;
  • profile or post link;
  • visible notification snippet;
  • signal type and receipt time;
  • limited metadata such as email subject, sender and message ID.

The current ingestion path is designed to store these normalised fields rather than the raw email body. The ingest credential is stored as a hash rather than as the original token.

4. User-supplied LinkedIn posts and screenshots

You can bring a post into the workflow yourself by supplying text, a link or a screenshot. When you upload a screenshot for extraction, the image is sent to the OpenAI API so that visible author, organisation and post text can be extracted. The extraction endpoint is configured not to cache the response, and the screenshot is not intentionally written to the Deeper Conversations application database by that endpoint.

The extraction prompt is designed to use only what is visibly present in the screenshot and not infer hidden identity details or other private characteristics.

5. What OpenAI receives

AI processing depends on the feature you invoke. A drafting request can include selected context such as:

  • conversation title, source and summary;
  • the user's configured theme;
  • a suggested angle or requested point of view;
  • recommended engagement type;
  • selected underlying source summaries;
  • Voice DNA settings such as directness, formality, warmth, sentence variation, comfort challenging, and preferred or avoided writing patterns.

A screenshot extraction request sends the user-supplied screenshot and an instruction to extract only visible information.

We do not need to send the user's entire database to OpenAI to generate a draft. Only the context required for the feature should be supplied.

6. Does anyone train AI on this data?

Design My Thinking does not train a general-purpose AI model on your content.

Deeper Conversations uses the OpenAI API rather than the consumer ChatGPT product. OpenAI currently states that API inputs and outputs are not used to train its models by default unless the API customer explicitly opts in to data sharing. We do not intend to opt Deeper Conversations user traffic into model training without first changing our disclosures and, where appropriate, seeking consent.

OpenAI may still retain API inputs and outputs for a limited period for service operation, security and abuse monitoring. Standard API retention can be up to 30 days for many uses, subject to the particular endpoint, account settings, legal requirements and future policy changes.

7. What AI is allowed to do

AI can help:

  • refine relevance;
  • interpret a professional conversation;
  • suggest agree-and-extend, challenge or reframe positions;
  • extract visible text from a screenshot;
  • generate a starting draft in the user's configured voice.

AI is not the final decision-maker. The product is intentionally designed so that a human decides whether to engage and what is ultimately published.

8. What the product deliberately does not do

  • No LinkedIn scraping. The product is not designed to crawl or scrape LinkedIn pages.
  • No automated LinkedIn posting. Drafts stay drafts until the user chooses what to do with them.
  • No required LinkedIn archive. Archive import is optional.
  • No private-message archive import. Message files are rejected by the current importer.
  • No advertising profile. We do not currently use behavioural advertising trackers in Deeper Conversations.
  • No sale of personal information. User data is not a product we sell.
  • No sensitive-person inference by design. The service is not intended to infer sensitive attributes about professional contacts.

9. Where information is processed

The main application database is currently hosted using Supabase in a Sydney region. The application itself is hosted on Vercel. AI requests are processed by OpenAI. Some processing and support therefore occurs outside Australia or may involve international subprocessors.

We will update this page if the core hosting architecture materially changes.

10. Deleting your data

You can request deletion by emailing hello@designmythinking.xyz. General user-linked data is intended to be removed from active systems within 30 days of a valid account deletion request, subject to limited backups, security records or legal requirements.

If Deeper Conversations begins receiving content through an official LinkedIn API, API-derived LinkedIn data and access tokens will be deleted according to LinkedIn's applicable developer rules, which can require immediate deletion on request or account closure.

11. Questions

This page is meant to make the architecture understandable rather than bury the important points in legal language. If something is unclear, email hello@designmythinking.xyz. The formal Privacy Policy and Terms of Use apply alongside this explanation.
